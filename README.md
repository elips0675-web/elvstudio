# Elv Studio — сайт продаж и продукт Elv Kit

Репозиторий содержит две вещи сразу:

1. **Сайт продаж** (`themes/elv-studio`) — лендинг студии, который продаёт готовый
   сайт для бизнеса и отдельные модули.
2. **Сам продукт** (`plugins/elv/kit`) — плагин Elv Kit для October CMS 4.x:
   онлайн-запись, заказы и оплата, обратная связь, подписка, блог, поиск,
   калькулятор сметы и лицензии.

Живая демо-версия витрины: **https://elvstudio.vercel.app** — статический экспорт
этого же сайта, собирается командой `php tools/export-static.php`.

Продукт версионируется отдельно: плагин — `plugins/elv/kit/updates/version.yaml`
(сейчас 1.0.6), тема — `themes/elv-studio/version.yaml` (1.0.0).

## Что продаёт сайт

| Продукт | Что это |
|---|---|
| **Elv Kit** | Тема + плагин: сайт с онлайн-записью, продажей товаров, оплатой картой, блогом и админкой |
| **Шаблон** | Только тема: страницы для сайта компании — главная, новости, события, услуги, каталог, контакты |
| **Модули** | Отдельные разделы: запись, магазин, формы обратной связи, блог |
| **Тарифы** | `single` — один сайт, `multi` — до 5 сайтов, `extended` — без ограничений |

Названия тарифов, их число, цены и состав живут в настройках и в таблице версий
прайса, а не в шаблонах. Ключи `single`/`multi`/`extended` неизменны: на них
ссылаются заказы и лицензии.

## Что работает

### Онлайн-запись
- Услуги — из настроек (`booking_services`): код, название, длительность, цена,
  описание, иконка. Пустое поле — раздел честно пишет «Запись временно
  недоступна», а не показывает выдуманные услуги.
- Слоты строятся на 14 дней вперёд (по умолчанию), занятый слот не продаётся
  дважды: проверка и запись идут в одной транзакции.
- Клиент получает подтверждение, администратор — уведомление; отмена
  освобождает слот. На демо-стенде письма пишутся в лог (`MAIL_MAILER=log`).

### Заказы и оплата
- Тариф выбирается на `/pricing/`, кнопки ведут на `/order/?product=…&plan=…`.
- Оплата: ЮKassa, Stripe или mock-режим для локальной разработки. Режим —
  из настроек, mock принудительно запрещён в production.
- Заказ фиксируется только по подписи вебхука или повторной проверке статуса;
  повторный вебхук не создаёт второй платёж.
- После оплаты заказ получает лицензию и доступ к ZIP по токену
  `/download/{token}`; неоплаченному заказу архив не отдаётся.
- Без галочки согласия заказ не создаётся (`consent` => `accepted`), а в `meta`
  заказа сохраняется след: `consent_at`, `consent_ip`, `consent_ua`,
  `terms_version` (хэш файла оферты) и `terms_url`. В карточке заказа это поле
  «Согласие с офертой» — ответ на чарджбэк «я ничего не принимал».

### Лицензии
- `POST /api/v1/license/activate` — активация по домену (хранится хэшем).
- `GET /api/v1/license/stats` — статистика, если включена в настройках.
- Лимит доменов считается по тарифу в одном месте — `Catalog::planDomainLimit()`.

### Обратная связь и подписка
- Формы под CSRF, `throttle` и honeypot; сообщения попадают в админку.
- Подписка — double opt-in: письмо с токеном, подтверждение
  `/subscribe/confirm/{token}`, отписка `/unsubscribe/{token}`.

### Блог
- Статьи, рубрики и технический раздел — из админки, а не из шаблона.
- Подборки на `/blog/` строятся по рубрике (`Blog::byCategory()`), поэтому
  переименование статьи не ломает ссылки, а пустая рубрика не рендерится.
- Пагинация со своим canonical и title, фильтры `?category=`, `?tag=`, `?q=`
  закрыты от индекса, страница за последней — 404.
- RSS, sitemap и `llms.txt` собираются из тех же данных.

### Поиск
- Свой индекс (`/search-index.json`) и свой скрипт, без внешних сервисов.
- Синонимы, фильтр по типу (страницы/блог), подсветка совпадений.

### Консультант
- Ответы по правилам, без внешнего AI и без отправки данных наружу.
- Услуги и ссылка на них — из настроек (`chat_services`); пустой список даёт
  нейтральный ответ, а не рекламу чужих услуг.
- Нецензурная лексика отсекается фильтром, ссылки канонические — со слэшем.

### Калькулятор сметы
- Считает тариф + модули по действующим ценам из прайса.
- Выгружает PDF-смету (`/calculator/quote.pdf`).
- Рекомендации и FAQ — из настроек, без зашитых текстов.

### SEO и скорость
- CSS и JS встроены в HTML с nonce, иконки — инлайновые SVG, внешних CDN
  и трекеров нет. Исключение — `/search/`: индекс и скрипт вынесены отдельно,
  чтобы не раздувать общий бюджет.
- Один адрес на страницу: `/blog` → 301 на `/blog/`, у пагинации свой canonical.
- JSON-LD: Organization, WebSite, SoftwareApplication, Product, FAQPage,
  BlogPosting, BreadcrumbList — только когда данные реально есть.
- Заголовки безопасности: CSP с nonce (без `unsafe-inline`), `X-Frame-Options`,
  `Referrer-Policy`, `Permissions-Policy`, `X-Content-Type-Options`.

### Настройки (вкладки)

| Вкладка | Что настраивается |
|---|---|
| Бренд | Название, подпись под логотипом, продавец в документах, описание |
| Меню | Пункт «Продукты» и его список |
| Контакты | E-mail, телефон, Telegram, WhatsApp, GitHub, документация, демо |
| Виджет | Включение консультанта, услуги и ссылка на них |
| Продажи | Валюта, режим оплаты, тарифы и их видимость, почта уведомлений, демо-ссылки, ключи ЮKassa/Stripe |
| Калькулятор | Включение, дата цен, примечания по хостингу и поддержке |
| Лицензии | API-токен, публичная статистика |
| SEO и аналитика | Google Analytics, Яндекс.Метрика, вебвизор |
| FAQ | Общий блок, калькулятор, услуги, SEO, статьи |
| Запись | Услуги записи |

Пустые настройки — не ошибка: шапка, футер, FAQ и разделы просто не показывают
блок, а не печатают наш текст-заглушку. Демо-значения ставит только
`php artisan elv:kit:demo`.

Название бренда в шаблонах не зашито: шапка, подвал, оферта, политика
конфиденциальности, контакты, письма и смета берут его из настроек. На чистой
установке это «Elv Kit» — покупатель меняет имя один раз на вкладке «Бренд»:
`brand_name` — название продукта в заголовках и логотипе, `brand_subtitle` —
необязательная подпись под логотипом (например, название студии; пусто — подписи
нет), `legal_name` — продавец в оферте, политике, контактах и копирайте (пусто —
подставляется `brand_name`).

`composer install`.

## Требования

- PHP 8.3+ (`pdo_mysql`, `mbstring`, `json`, `gd` для OG-картинки, `zip` для сборки поставки)
- MySQL 8.0+ или MariaDB 10.6+
- Composer 2

## Язык

Интерфейс витрины, админки и писем — только русский (RU). Английской версии
в поставке нет: тексты страниц лежат в Twig-файлах темы (`themes/elv-studio/pages`,
`partials`), их можно перевести самостоятельно, но готового перевода и
переключателя языков мы не поставляем. Даты, числа и валюта форматируются
по русским правилам; валюта задаётся в настройках (`currency`).

## Установка

```bash
composer install
cp .env.example .env
php artisan key:generate
```

В `.env` задать базу и адрес:

```
APP_URL=http://localhost:8090
DB_CONNECTION=mysql
DB_DATABASE=elv_studio
DB_USERNAME=root
DB_PASSWORD=
ACTIVE_THEME=elv-studio
```

Создать пустую базу, затем:

```bash
php artisan october:migrate
php artisan elv:kit:demo
php artisan serve --port=8090
```

`elv:kit:demo` наполняет каталог, статьи и слоты бронирования идемпотентно;
`elv:kit:reset` удаляет демо-данные, `elv:kit:package` собирает ZIP поставки.

## Быстрый запуск на Windows

1. Запустить MySQL (Laragon, порт 3306).
2. Двойной клик по `запуск.bat`: скрипт находит PHP и MySQL, поднимает сервер
   на `0.0.0.0:8090` с OPcache, ждёт порт и открывает браузер.
3. Админка — `http://localhost:8090/admin`, логин `admin`, пароль в
   `.local/admin-credentials.md` (файл не коммитится).

Если сервер уже поднят, `админка.bat` просто откроет страницу входа.
Порты по умолчанию: сайт `8090`, MySQL `3306`.

## Боевое окружение

Стенд и прод отличаются окружением, а не кодом. Чек-лист —
`docs/production-deploy.md`: `.env` (`APP_ENV=production`, `APP_DEBUG=false`,
`APP_URL` по HTTPS, `QUEUE_CONNECTION=database`, SMTP и адрес отправителя на
своём домене, ключи ЮKassa/Stripe), воркер очереди под supervisor, Cron
`schedule:run`, вебхуки `/payment/yookassa` и `/payment/stripe`, бэкапы.

Проверка: `php tools/production-check.php --strict` — на проде 0 предупреждений.
На стенде строгий режим падает намеренно: там `APP_ENV=local`, `APP_DEBUG=true`,
очередь `sync`, почта в лог и нет платёжных ключей.

## Сборка продукта

```bash
php artisan elv:kit:package          # товарный ZIP: тема, плагин, README, LICENSE
php artisan elv:kit:package --demo   # вариант с демо-данными для лендинга
```

Архив собирается в `storage/app/kit/elv-kit-<версия>.zip`. Версия берётся из
`updates/version.yaml` — это единственный источник. Демо-статьи блога
(`demo/blog.json`) в товарный архив не попадают: у покупателя блог пуст до его
собственных статей.

## Честность данных

- Цены и дата «Цены обновлены» — из версий прайса; выдуманные цифры и даты —
  дефект, а не заглушка.
- На пустой базе витрина работает: `/pricing/` пишет «Прайс пока пуст»,
  `/order/` объясняет, почему заказ закрыт, `?product=<несуществующий>` — 404,
  `/modules/<несуществующий>/` — 404 с `noindex` (страница модуля не выдумывает
  товар). Проверка: `node tools/check-empty-install.mjs --base=…`.
- Контакты, услуги, FAQ, демо-ссылки и пункты меню — из настроек, а не из кода.
- Отзывов, счётчиков и кейсов, которых не было, на сайте нет.

## Безопасность и данные

- Формы под `web` + CSRF + `throttle`, honeypot в каждой форме.
- Оплата: редирект на ЮKassa или Stripe, фиксация только по подписи или
  повторному GET статуса; mock-режим отключён при наличии ключей и вне `local`.
- Секреты живут в `.env`; в репозиторий попадает только `.env.example`.
- База, заказы и брони остаются на своём сервере: внешних трекеров и CDN нет.

## Ограничения демо-стенда

- `MAIL_MAILER=log`, `QUEUE_CONNECTION=sync` — письма пишутся в лог, очередь
  выполняется сразу. Для боевого сайта нужны SMTP и `queue:work`.
- Оплата локально — mock: заказ помечается оплаченным без шлюза. В production
  mock запрещён, нужны ключи ЮKassa или Stripe.
- Пароль администратора лежит в `.local/admin-credentials.md` (не коммитится);
  на боевом сайте его нужно сменить.
- Демо-данные (товары, цены, статьи, услуги) — вымышленные и ставятся только
  командой `elv:kit:demo`; на пустой базе сайт работает без них.
