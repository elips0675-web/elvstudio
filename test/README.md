# Папка `test` — вход для внешнего AI-аудита

Репозитории: витрина — `D:\Elv Landing` → https://github.com/elips0675-web/elvstudio,
продукт — `D:\October CMS` → https://github.com/elips0675-web/OctoberCMS,
стенд — `D:\Elv test` → https://github.com/elips0675-web/Elvtest.

Здесь лежит **самодостаточный срез витрины Elv Studio** для анализа
в браузере (DeepSeek, Qwen и другие модели без доступа к диску).

| Файл | Что внутри |
|---|---|
| `Для анализа.txt` | стек, роль площадок, что откуда (ядро/магазин/кастом), карта кода, тесты и гейты, факты HEAD, бэклог, ограничения, вопросы аудитору |
| `ai-chat/` | снимок кода для глубокого разбора Консультанта, поиска и карты сайта: `Chat.php`, `Search.php`, `TextFilter.php`, `ChatController`, `widget.js`, `chat-check.php`, `booking-check.php`, `check-php.mjs`, `Plugin.php`, `composer.json`, `theme.yaml`, `sitemap.htm`, `Seo.php`; собирается `node tools/build-test-snapshot.mjs` |

## Как пользоваться

1. Открыть `Для анализа.txt` и загрузить его в чат целиком.
2. Задать вопросы из раздела «Что смотреть аудитору» или свои.
3. Если модели нужен конкретный файл — назвать путь из карты кода
   (`plugins/elv/kit/classes/Seo.php` и т. п.); этот файл ей отдельно
   и передать.
4. Если чат не имеет доступа к диску и нужен разбор кода — загрузить
   `ai-chat/ALL-IN-ONE.txt` или отдельные файлы из `ai-chat/`.
   Какой набор выбрать, написано в `ai-chat/README.md`.

## Что здесь **не** лежит

- `.env`, пароли, ключи, дампы БД.
- `vendor/` и `modules/` (ядро October) — их нет и в репозитории.
- Полный бэклог и журнал — `Что доделать.txt` и `Что сделано.txt` в корне.

## Когда обновлять

- После каждого закрытого этапа: числа статей/страниц/гейтов и бэклог
  меняются — править разделы 5–8 и дату среза в шапке.
- Снимок кода в `ai-chat/` пересобирается одной командой
  `node tools/build-test-snapshot.mjs`: она берёт дату, Stage и хеш `HEAD`,
  перезаписывает `02`–`08` и `ALL-IN-ONE.txt`. Вручную правится только
  `test/ai-chat/01-context.txt` — там проза, а не код.
- Перед отправкой на аудит проверить HEAD (`git log --oneline -1`) и то,
  что числа совпадают с фактическим прогоном `npm run check`.

Файл коммитится в репозиторий (`test/` не в `.gitignore`).
