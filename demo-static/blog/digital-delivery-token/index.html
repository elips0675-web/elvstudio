Выдача файла по токену: почему нельзя давать ссылку на storage

Ссылка на файл расходится по чатам за минуту. Показываем схему с токеном, проверкой оплаты и потоковой отдачей.

Цифровой товар нельзя отдавать по прямой ссылке на storage: ссылка расходится по чатам за минуту. Правильный путь — короткий токен, который проверяется на сервере при каждом скачивании.

Как устроен токен

  1. После оплаты генерируется случайная строка: 32 байта из random_bytes.
  2. Токен сохраняется у заказа, а в письме уходит ссылка вида /download/{token}.
  3. Скачивание проверяет статус paid и отдаёт файл через поток.

Чего не делать

  • Не строить токен из номера заказа: его можно перебрать.
  • Не хранить файл в публичном каталоге.
  • Не отдавать ZIP до оплаты, даже если очень просят.
  • Не логировать сам токен целиком.

Срок жизни и повторы

Ссылка должна работать после оплаты и оставаться рабочей для повторного скачивания. Ограничение по времени добавляют, если товар обновляется: старые версии можно закрыть. Число скачиваний обычно не ограничивают — человек имеет право переустановить купленное.

Заголовки

Ответ на скачивание: Content-Type application/zip, Content-Disposition attachment с безопасным именем, Cache-Control private и no-store. Страница не должна попадать в поиск: X-Robots-Tag noindex.

Токен — это не пароль. Это право на конкретный файл, выданное после конкретной оплаты.

В Elv Shop проверка статуса и выдача файла разнесены: контроллер не знает, как устроен ZIP, а сервис выдачи не знает, как устроена оплата.

Проверьте три вещи: ссылка не работает до оплаты, после возврата перестаёт работать, а в логах нет полного токена. Если ссылка живёт в письме, она должна переживать повторное скачивание.
