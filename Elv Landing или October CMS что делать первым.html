02Почему витрина первая

  1. Она — единственный канал продаж обоих продуктов. Пока витрина не готова, продавать нечего: шаблон из D:\October CMS по правилам продаётся именно через неё (October CMS/AGENTS.md:14).
  2. Она ближе к «продаётся». 18–19.11 закрыты упаковка ZIP, отделение демо от товара, нейтральный бренд, тарифы и FAQ из настроек (Что доделать.txt:349-538). В коде осталось четыре пункта, а не тридцать.
  3. У October CMS P0 — это инфраструктура и данные владельца, а не код. Хостинг и домен (M17), реальные контакты (P0-6), права на 20 демо-фото (P0-7), бэкапы (P0-8), CI (P0-9). Плюс крупные фичи: поиск BM25 (M8), POST /api/bookings (P1-16), бэкенд чата (P1-17).
  4. Демо шаблона — статический снимок, продавать он не может. Оно уже опубликовано и отдаёт 200 (elips0675-web.github.io: 110 страниц, sitemap 107), но формы, брони, оплата и админка там отключены (October CMS/README.md:24-28). Витрина принимает заказы, лицензии и выдаёт ZIP — то есть зарабатывает именно она.
  5. Общий ресурс — данные владельца. Цены, провайдеры хостинга, кейсы, валюта, SLA блокируют обе площадки. Пока их нет, двигать код витрины выгоднее: там меньше зависимостей от чужих решений.

04Потом — D:\October CMS

Четыре блока по возрастанию стоимости. Первые два не требуют данных владельца.

  1. Блок A готово Публичное демо шаблона — уже опубликовано

    Демо живёт на GitHub Pages: elips0675-web.github.io — 110 страниц, sitemap 107 адресов, неизвестный путь отдаёт 404. Алиас octobercms.vercel.app по-прежнему 404, и в README публичной ссылки нет (Что доделать.txt:67-73) — документ отстал от факта.

    ОсталосьВписать адрес в README и GitHub About, а снимок пересобирать после правок: php tools/export-static.php --origin=https://elips0675-web.github.io.

  2. Блок B P0 Бэкапы и CI

    P0-8: скрипт в tools/, восстановление прогнано один раз и сверено, RTO записан (:124-137). P0-9: workflow на push/PR — PHPUnit, composer audit, гейты на поднятом serve (:139-160).

    ПочемуСейчас «миграции forward-only» — лозунг: восстановление ни разу не проверялось.

  3. Блок C P1 Крупные фичи

    Поиск BM25 — M8 (:298-307); POST /api/bookings с идемпотентностью и 409 на занятый слот — P1-16 (:218-234); бэкенд чата — P1-17 (:236-251).

  4. Блок D P1 Контент и хостинг

    59 позиций из 91 без фото (P1-11), демо-подсказка «часть слотов занята» (P1-9), затем M17: хостинг, домен, HTTPS, cron, внешняя проба /health.

Почему не наоборот Даже если начать с шаблона, первым шагом всё равно будет импорт демо и P0-8/P0-9: поиск и API без бэкапов и сборки — это функция, которую нельзя выпускать.

05Когда порядок обратный

Цель — сдать библиотечный шаблон

Тогда первым идёт October CMS.

  • Демо уже на GitHub Pages — проверить свежесть снимка и пересобрать после правок.
  • Затем P0-8 и P0-9 — это фундамент релиза.
  • Поиск и API — после, но до публикации на своём домене.

Цель — деньги от Elv Kit

Тогда порядок однозначный.

  • Только витрина: шаги 1–4 из раздела 03.
  • Октябрьский шаблон ждёт: он не влияет на продажу Elv Kit.
  • Хостинг и ключи — параллельно, силами владельца.

06Замечания по бэклогам

Устаревший пункт в витрине

В Что доделать.txt:508-513 написано, что у темы нет composer.json, version.yaml и screenshot.png. Файлы есть — добавлены в Stage 63 (:514-522). Устарел только текст пункта, работа не нужна.

Расхождение текстов на 33 страницах

В October CMS это P2-42 (:31) — следствие нейтрального бренда с Stage 36, а не баг. Гейт check-dom-parity --structure по структуре зелёный.

Один класс дефекта в обоих проектах

«Контент про нас, а не универсальный». В витрине он закрыт для плагина — услуги, FAQ, блог и бренд из настроек (Stage 67, 71–74), осталась тема. В шаблоне висит как P2-42. Логично закрыть его в витрине первым и перенести рецепт в шаблон.

README шаблона отстал от факта

В October CMS/README.md:30-33 написано, что публичной ссылки у шаблона нет: «octobercms.vercel.app ещё не развёрнут». При этом демо на GitHub Pages отдаёт 200 и содержит 110 страниц. Не блокер, но при выборе порядка работ вводит в заблуждение.

Деревья чистые

git status в обоих каталогах пуст, поэтому переключение между проектами ничего не потеряет.
