## 1. Инсталляция и запуск

- Отдельная инсталляция October CMS 4.4.13 (Laravel 12.71.0, PHP 8.3.30,
  MySQL 8.4.3), база `elv_studio`, `APP_URL=http://localhost:8090`.
- Плагин `plugins/elv/kit`: модели, миграции 10 таблиц `elv_kit_*`, маршруты
  форм, оплата, лицензии, SEO, админка, демо-данные.
- Тема `themes/elv-studio`: макет, партиалы, страницы, инлайн CSS/JS.
- Запуск: `запуск.bat` (PHP + MySQL + `artisan serve`), `админка.bat`.

Проверено: `/` и `/admin` отвечают 200, миграции применились, демо-данные
созданы. По ходу созданы отсутствовавшие каталоги `storage/cms/*`,
`storage/app/*`, `storage/temp/*`; исправлены `csrf_token` в Twig и чтение
`meta_title`/`meta_description` из October.

## 2. Стабильность, брендинг и скорость

- `server.php` отдаёт статику через `tools/serve-static.php`: правильный
  `Content-Type`, gzip, ETag, `Cache-Control`.
- Брендинг админки заменён с библиотечного на Elv Studio: SVG-знаки,
  `config/backend.php`, чистый CSS.
- HTML сжимается `CompressResponse`; CSS/JS минифицируются `Assets`.
- Удалён `.reveal { opacity: 0 }`, который держал карточки невидимыми до
  срабатывания IntersectionObserver; создан отсутствовавший favicon.

Проверено: Lighthouse mobile/desktop 100, gzip 107 621 → 18 586 байт,
`/admin` грузит стили, вход работает.

## 3. Виджет: контакты, форма, ИИ-чат

- Виджет перенесён из темы в `plugins/elv/kit/views/widget.htm` и
  `assets/widget.{css,js}`; тема только подключает его.
- Меню: Telegram, WhatsApp, телефон, e-mail, «Обратная связь»,
  «ИИ-консультант»; форма пишет в `elv_kit_messages`.
- `Classes\Chat` отвечает по каталогу и настройкам без внешних ключей;
  `POST /chat` имеет отдельный лимит 40/мин.
- `Classes\TextFilter` ловит грубые слова с пробелами, повторами и латинскими
  похожими буквами; в формах заказа/брони/обратной связи сознательно не
  включён.
- Найден и исправлен баг `Assets::minifyJs`: `preg_split('~\R~')` без `u`
  рвал русские строки по байту `0x85`; заменено на явные переводы строк.

Проверено: форма создаёт строку в БД, чат отвечает на 12 вопросов, три
конфигурации настроек (с контактами/без, с чатом/без) ведут себя правильно,
`node --check` и `php -l` чисто, Lighthouse 100.

## 4. Страницы, маршруты и Vercel

- Созданы все страницы темы: `kit`, `modules`, `module`, `pricing`, `demo`,
  `docs`, `blog`, `blog-post`, `order`, `order-success`, `booking`, `feedback`,
  `contacts`, `terms`, `privacy`, `sitemap`, `404`.
- Динамические страницы падали с 404 из-за `this.param('slug')`; в October
  `param` — массив, заменено на `this.param.slug`.
- Хлебные крошки получили `crumbs` во всех страницах; добавлен `Product`
  JSON-LD; создан `og-default.png` 1200×630.
- gzip не работал на `/modules/*` из-за слишком широкого skip-листа; заменён
  на конкретные каталоги ядра.
- Vercel не исполняет PHP: добавлен `tools/export-static.php`, `vercel.json`,
  `.vercelignore`; статический снимок отдаёт страницы без PHP.

Проверено: 27 URL — 200, неизвестный адрес — 404, HTML сжимается,
`demo-static/` открывается, формы/чат/оплата в статике отключены.

## 5. Гейты и найденные ими дефекты

- `tools/check-urls.mjs` — обход внутренних ссылок и 404.

- `tools/check-headers.mjs` — CSP с nonce, gzip, `X-Frame-Options`, nosniff,

- `tools/check-budget.mjs` — лимиты HTML/CSS/JS/gzip.
- `tools/check-orphans.mjs` — страницы ↔ sitemap, неиспользуемые партиалы и

  заменён на каталоги ядра.
- Гейт SEO нашёл короткие description на страницах модулей; описание теперь
  берётся из `description`, а не из `tagline`.

Проверено: `npm run check` зелёный, Lighthouse 100/100/100/100, ручные проверки
