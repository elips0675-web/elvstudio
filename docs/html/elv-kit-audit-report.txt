2. НАХОДКИ И НЕДОЧЁТЫ В КОДЕ (PHP / JS)
--------------------------------------------------------------------------------
[1] Конфликт триггера 'ссылк' в Chat.php (строки ~65 и ~90) — КРИТИЧНО
    Проблема: Корень 'ссылк' включён в триггеры явного поиска по блогу (строка
    ~65) раньше ветки доставки файлов ['скачать', 'доставк', 'zip', 'архив',
    'токен', 'ссылк'] (строка ~90). Запрос «не работает ссылка на скачивание»
    уходит в поиск статей вместо инструкции по получению архива.
    Решение:  Убрать 'ссылк' из триггеров явного поиска.

[2] Конфликт триггера 'услуг' в Chat.php (строки ~113 и ~152) — СРЕДНЕ
    Проблема: Корень 'услуг' привязан к блоку онлайн-записи. Вопрос «какие
    услуги вы оказываете» возвращает описание модуля бронирования вместо
    перечня услуг студии (/services/).
    Решение:  Выделить отдельный ответ для запросов про услуги студии со ссылкой
              на /services/, а в блоке записи оставить ['брон', 'слот', 'запис'].

[3] Двойной SQL-запрос к БД в Chat.php + Search.php — СРЕДНЕ
    Проблема: При неизвестном вопросе Chat::answer() вызывает Search::query(),
    а затем в isNonsense() снова вызывает Search::query() в цикле для каждого
    слова. Каждый вызов заново делает SQL-запрос Post::query()->published().
    Решение:  Добавить статический кэш protected static ?array $cache = null;
              в Search::index() на время одного HTTP-запроса.

[4] Отсутствие стемминга в Search.php и search.js — КРИТИЧНО ДЛЯ UX
    Проблема: Поиск ищет строгое вхождение подстроки (str_contains / indexOf).
    Запросы «оплаты», «тарифами», «статью», «бронирования» не находят слова
    «оплата», «тарифы», «статья», «бронирование».
    Решение:  Добавить обрезку базовых русских окончаний для слов длиннее 4
              символов в оба файла (~10 строк кода, ~250 байт в JS).

[5] Ложные срабатывания латинского TextFilter.php (строки ~95–108) — СРЕДНЕ
    Проблема: Латинские основы проверяются без границ слова, поэтому обычные
    слова вроде shitake или cocktail блокируются как грубость.
    Решение:  Добавить границы слова (?<![\p{L}\p{N}]) и (?![\p{L}\p{N}]) для
              латинских паттернов.

[6] Активные чипы при состоянии busy в widget.js (строка ~188) — НИЗКО
    Проблема: Пока идёт запрос POST /chat, кнопки быстрых подсказок (чипы)
    остаются визуально кликабельными, хотя клик по ним игнорируется.
    Решение:  В setBusy(state) проставлять chip.disabled = state.

4. ОТВЕТЫ НА 6 ВОПРОСОВ ИЗ СРЕЗА (01-context.txt)
--------------------------------------------------------------------------------
Q1. Достаточно ли проверки «нет ни одного слова из индекса» для бессмыслицы?
A1. Да, для отсечения случайного набора букв («абырвалг», «фывап») этого
    достаточно; словарь или модель не нужны. Чтобы не гонять поиск по БД дважды,
    достаточно проверять наличие в запросе слова >= 3 букв с хотя бы одной
    гласной.

Q2. Правильно ли виджет удаляет пузырь пользователя при rejected?
A2. Только при грубости (TextFilter::has) — так чат остаётся чистым. При
    непонятном запросе или опечатке (isNonsense) пузырь лучше оставлять
    (rejected: false), чтобы пользователь видел свой ввод и мог поправить его.

Q3. Где узкие места клиентского поиска?
A3. Главное узкое место — отсутствие стемминга (падежи и числа не находятся).
    Размер search-index.json для 94 документов не является проблемой. Нечёткий
    поиск опечаток добавлять не стоит: он съест жёсткий лимит 20 КБ JS.

Q4. Не раздувает ли Search ответственность, или разделение преждевременно?
A4. Разделение преждевременно. Класс занимает ~240 строк, логика линейная.
    Дробить его на несколько классов ради 94 документов — избыточно.

Q5. Корректна ли группировка карты сайта /sitemap/?
A5. Да, структура логична: коммерческие разделы и модули на первом экране,
    блог не превращён в простыню из 67 ссылок, а все статьи доступны роботам
    через /sitemap.xml и пагинацию /blog/.

Q6. Какие 3–5 правок дадут наибольший эффект без нового продуктового кода?
A6. 1) Стемминг окончаний в Search.php и search.js;
    2) Сохранение пузыря пользователя при опечатках в чате (rejected: false);
    3) Разведение триггеров 'ссылк' и 'услуг' в Chat.php;
    4) Кэширование Search::index() в памяти HTTP-запроса;
    5) Уточнение формулировок про «0 платежей» и «установку» на главной.
