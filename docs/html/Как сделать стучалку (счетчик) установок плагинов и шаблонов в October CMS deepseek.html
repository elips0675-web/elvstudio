Как сделать стучалку (счетчик) установок плагинов и шаблонов в October CMS

В October CMS нет единой «кнопки», которая считает установки всех сторонних расширений, потому что установка может происходить разными путями: через Marketplace, через Composer, копированием файлов вручную и т. д. [reference:0]. Однако задачу можно решить несколькими способами — выбор зависит от того, чьи установки вы хотите считать (своего продукта или всех подряд) и где нужно показывать цифру.

Коротко: для собственного плагина проще всего использовать миграции (однократный инкремент при установке). Для гибкого подсчёта любых событий — плагин SunLab.Measures. Для продуктов, опубликованных в Marketplace, статистика уже ведётся автоматически.

Способ 1: Встроенная статистика October CMS Marketplace самый простой

Если ваш плагин или шаблон опубликован в официальном Marketplace, October CMS уже считает уникальные установки для бесплатных продуктов и показывает их на странице продукта и в панели автора. [reference:1]

Ограничение: этот счётчик работает только для продуктов, распространяемых через Marketplace. Если вы ставите плагины вручную или через приватный Composer-репозиторий, цифра не появится.

Что использовать: личный кабинет автора в October CMS → раздел вашего продукта → статистика установок.

Способ 2: Собственный счётчик на миграциях для своего плагина

Самый надёжный способ посчитать уникальные установки вашего плагина — сделать это в миграции. Миграции плагина выполняются ровно один раз при установке (и при обновлении, если версия миграции новая), поэтому инкремент в миграции не будет срабатывать повторно при обычной загрузке сайта.

Шаг 1. Создайте таблицу для счётчика

В плагине создайте миграцию, которая создаст таблицу и сразу добавит в неё одну запись (это и будет «+1 установка»).

<?php
// В файле миграции вашего плагина, например:
// plugins/vendor/plugin/updates/create_installations_table.php

use October\Rain\Database\Updates\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;
use Illuminate\Support\Facades\DB;

class CreateInstallationsTable extends Migration
{
    public function up()
    {
        Schema::create('vendor_plugin_installations', function (Blueprint $table) {
            $table->increments('id');
            $table->timestamps();
        });

        // Однократный инкремент при установке
        DB::table('vendor_plugin_installations')->insert([
            'created_at' => now(),
            'updated_at' => now(),
        ]);
    }

    public function down()
    {
        Schema::dropIfExists('vendor_plugin_installations');
    }
}

Шаг 2. Получите количество установок

В любом месте плагина (компонент, модель, бэкенд-контроллер) можно получить цифру простым запросом:

use Illuminate\Support\Facades\DB;

$installCount = DB::table('vendor_plugin_installations')->count();

Для шаблонов подход аналогичен, но у темы нет миграций. Можно включить в комплект темы небольшой плагин-компаньон, который будет считать активации темы через событие cms.theme.activated (если вы отслеживаете именно активации), либо использовать отдельный плагин-счётчик, который устанавливается вместе с темой.

Способ 3: Плагин SunLab.Measures гибкий

SunLab.Measures позволяет создавать произвольные счётчики и статистику поверх любой модели October CMS. [reference:2] Он не «считает установки» из коробки, но даёт удобный механизм инкремента и хранения чисел, который можно привязать к событию установки.

Когда это удобно

  • Нужно считать не только установки, но и другие события (активации, просмотры, скачивания).
  • Нужна единая система счётчиков для нескольких моделей.
  • Вы хотите использовать готовое поведение Measurable вместо ручных SQL-запросов.

Как использовать

  1. Установите плагин: php artisan plugin:install SunLab.Measures.
  2. Добавьте поведение Measurable к модели, которую хотите считать. Например, если у вас есть модель Installation:
class Installation extends Model
{
    public $implement = ['SunLab.Measures.Behaviors.Measurable'];
}

Затем в миграции или в обработчике события установки вызовите:

$installation = new Installation();
$installation->incrementMeasure('installs');

Или через статический помощник:

use SunLab\Measures\Classes\MeasureManager;
MeasureManager::incrementMeasure($installation, 'installs');

Получить значение можно так:

{{ installation.getMeasure('installs').amount }}

Способ 4: Визуализация через DashMetrics для дашборда

Если счётчик уже собирается (любым из способов выше), но вы хотите видеть динамику в бэкенде October CMS в виде графиков и KPI, обратите внимание на DashMetrics. Плагин позволяет без кода строить графики по любой модели, включая количество установок, с группировкой по дням, неделям и месяцам. [reference:3]

Что использовать: после установки DashMetrics создайте датасет на основе таблицы установок и добавьте виджет на дашборд.

Как показать счётчик на сайте (фронтенд)

Если вы используете собственный счётчик на миграциях, проще всего вывести цифру через компонент или прямо в Twig-шаблоне страницы. Например, создайте компонент InstallCounter, который в методе onRun() возвращает количество записей из таблицы установок, и выведите его в шаблоне:

{{ __SELF__.installCount }} установок

Для анимированного отображения цифры можно использовать готовые решения вроде Animated Number Counter от Common Ninja — они встраиваются одной строкой кода и не требуют изменения логики подсчёта. [reference:4]

Что выбрать

  • Плагин уже в Marketplace → ничего не делайте, счётчик уже есть в панели автора. [reference:5]
  • Свой плагин, нужна одна цифра «установок» → способ 2 (миграция с инкрементом). Это минимальный код и максимальная надёжность.
  • Нужно считать разные события и удобно управлять счётчиками → способ 3 (SunLab.Measures).
  • Нужны графики и отчёты в бэкенде → добавьте DashMetrics поверх любого из способов сбора данных. [reference:6]
Важно: при подсчёте установок через миграции учитывайте, что миграция выполнится и при обновлении плагина, если вы добавите новую миграцию. Чтобы считать именно уникальные установки, не создавайте новых миграций, которые повторно инкрементируют тот же счётчик. Если нужна статистика по версиям, используйте отдельные таблицы или поля с версией. 🛠️ Сценарий 2: Прямая продажа через ваш сайт (кастомная схема) Если вы хотите продавать плагин напрямую, минуя Marketplace, то да, вам придётся реализовать свою собственную систему лицензирования. Именно в этом случае покупатель сообщает вам домен, а вы генерируете для него уникальный ключ. Однако важно понимать: этот ключ не будет иметь никакой силы в официальной экосистеме October CMS (он не даст покупателю доступ к обновлениям через Gateway). Это будет ваша внутренняя защита. Как это может работать технически: Вы создаёте на своём сайте простую форму или личный кабинет. Покупатель вводит домен, на котором хочет использовать плагин, и оплачивает покупку. Ваш скрипт генерирует уникальный ключ (например, хэш от домен + соль + секрет) и сохраняет в вашей базе связку ключ → домен. Вы передаёте этот ключ покупателю. Покупатель вводит его в настройках плагина на своём сайте. В коде вашего плагина вы добавляете проверку: плагин отправляет запрос на ваш сервер с указанием своего домена и введённого ключа. Ваш сервер проверяет, совпадает ли домен с тем, что был указан при покупке, иactive ли ключ. Если нет — плагин блокируется (как в примере из предыдущего ответа). 💎 Итог Штатный путь (Marketplace): Вы не управляете ключами. Покупатель использует свой Project Key, привязанный к его домену. Вы получаете деньги и поддержку от платформы. Прямой путь (свой сайт): Вы создаёте свою систему «домен → ключ». Это даёт вам полный контроль, но требует разработки и поддержки собственного сервера лицензий, и такой ключ не будет «пониматься» официальным Marketplace. Таким образом, фраза «покупатель говорит домен, я ему ключ» описывает именно кастомную схему, которую нужно реализовывать отдельно, если вы не хотите использовать механизмы Marketplace.
