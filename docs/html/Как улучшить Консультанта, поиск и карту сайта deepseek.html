1Консультант — Chat::answer, widget.js

Самый большой запас улучшений. Ответы работают, но UX и логика отсева оставляют пользователя без объяснений.

1.1. Не удалять пузырь пользователя при rejected Высокий

Сейчас виджет «убирает» пузырь. Пользователь не понимает, куда делось сообщение. Правильно — оставить пузырь и показать inline‑ошибку с кнопкой «Исправить». Это же снимает риск «визуального исчезновения» в Safari, который пока не проверен.

Сейчасmessage → rejected → пузырь скрыт
пользователь думает: «куда делось?»
Предлагаюmessage → rejected → пузырь остаётся
рядом: «Сообщение скрыто: нецензурная лексика» [Исправить]

1.2. Эвристика бессмыслицы ненадёжна — дешёвый слой правил Высокий

Сейчас: «нет ни одного слова из индекса» → rejected. Проблемы: редкое осмысленное слово (краудфандинг) → ложный отказ; бессмыслица с известным словом (абырвалг оплата) → проходит. Минимальная правка перед rejected:

// до rejected:
// 1) длина ≥ 2 и есть хотя бы одна гласная
// 2) нет трёх одинаковых символов подряд (аааа, фффф)
// 3) слово длиной ≥ 3 в индексе
//    ИЛИ в маленьком стоп-листе частых русских:
//    цена, как, что, где, можно, нужно

Плюс — логировать rejected в отдельную таблицу/файл. Это даст данные для калибровки без сбора персональных данных.

1.3. Интент‑классификация до поиска Высокий

Запрос «сколько стоит CRM» уйдёт в fallback‑поиск, хотя готовый ответ про тарифы уже есть. Добавьте rule‑based интенты до вызова Search:

ИнтентТриггерыДействие
pricingсколько, цена, стоит, тарифChat::pricing()
docsкак, настроить, установить, запуститьссылка на /docs/
bookingзаписаться, консультация, созвон/booking/
demoдемо, посмотреть, попробовать/demo/
contactсвязаться, написать, поддержка/feedback/

~40 строк PHP, но убирает самый частый класс «глупых» fallback‑ответов.

1.4. Действия после ответа Средний

  • followups: [{label, query}] — 2–3 подсказки («Сравнить тарифы», «Как запустить»);
  • feedback: true — виджет рисует 👍/👎, отправляет на /chat/feedback (анонимно, без текста сообщения). Без этого вы не узнаете, какие ответы бесполезны.

1.5. ChatController + антиспам Средний

  • Возвращать rejected: false спам‑боту — рабочая тактика, но зафиксируйте комментарием в коде, иначе следующий разработчик «починит»;
  • throttle:40,1 по IP обходится. Добавьте per‑session лимит (например, 15 сообщений / 5 минут) — счётчик в кэше по session()->getId().

1.6. TextFilter — false positives Средний

shitake → true задокументировано, но это баг. Минимум: проверять границы слова для латиницы (не матчить shit внутри shitake), для кириллицы — оставить подстрочный поиск. Или заведите TextFilter::$whitelist с 5–10 словами.

2Поиск — Search.php, search.js

Работает, но без морфологии пользователи будут уходить с пустым результатом на «оплату».

2.1. Главный пробел — морфология Высокий

phrase() нормализует, но indexOf ищет точное вхождение: «оплата» не найдёт «оплаты/оплате/оплату». Варианты по возрастанию сложности:

  • Стеммер Портера для русского (~150 строк JS/PHP) — режет до основы оплат. ~80% эффекта за вечер;
  • Синонимы‑словарь (10–20 групп): оплата/платёж/платить/оплатить, запись/бронирование/бронь, цена/стоимость/тариф/сколько стоит;
  • Опечатки: для слов ≥ 5 — расстояние Левенштейна ≤ 1, только если 0 точных совпадений.

2.2. Подсветка совпадений и сниппеты Средний

Добавьте <mark> вокруг найденных слов в title и description карточки — бесплатно повышает конверсию поиска.

2.3. Пагинация вместо жёстких 30 Низкий

found.slice(0, 30) — если результатов 100, пользователь видит 30 и не знает, что есть ещё. Добавьте «Показать ещё» или ?page=.

2.4. Аналитика запросов Высокий (долгосрочно)

Клиентский поиск не отправляет запрос на сервер — правильно для приватности. Но добавьте анонимный POST на /search/stats с {query_hash, results_count} (без IP, без сессии). Через месяц увидите, какие запросы дают 0 — это прямой список тем для блога. Иначе улучшаете поиск вслепую.

2.5. Индекс: тело статьи обрезано до 320 символов Средний

Для статей про SEO/оплату ключевые слова часто во второй половине. Поднимите лимит до 800–1000 для статей (не для страниц) — при 67 статьях это +30–40 КБ gzip, приемлемо. Либо индексируйте отдельно h2/h3 и первый абзац каждого раздела.

2.6. Кэш Search::index() Низкий

SeoController кэширует /search-index.json на 30 минут — хорошо. Но если Search::index() вызывается где‑то ещё (например, в elv_search_index() для шаблона), кэшируйте внутри класса по ключу theme + updated_at постов.

3Карта сайта и SEO — Sitemap.php, Seo.php

Большинство правок — мелкие, но заметные для Search Console и Яндекса.

3.1. Пустой FAQPage в JSON‑LD Высокий

faqNodeFromItems() возвращает узел даже при $items === []. Пустой FAQPage — это либо игнор, либо предупреждение в Search Console.

if ($items === []) {
    return [];  // и не добавлять в $graph
}

3.2. Organization без logo Средний

Google любит logo для организаций. Добавьте:

'logo' => static::base() . '/themes/elv-studio/assets/img/og-default.png'

Плюс sameAs расширить: VK, YouTube, Habr — если есть.

3.3. XML‑sitemap: changefreq / priority Низкий

Google игнорирует, Яндекс частично учитывает. Не критично, но для блога можно поставить monthly, для главной weekly, для услуг monthly. Дешёвая правка, улучшает читаемость для SEO‑аудита.

3.4. robots.txt: расширить Clean-param Низкий

Сейчас Clean-param: q&category&tag /blog/. Но ?q= может появиться и на других страницах. Правильнее:

Clean-param: q&category&tag&page

без привязки к /blog/ — Яндекс применит ко всем URL.

3.5. Человеческая карта сайта — добавить поиск Средний

/sitemap/ — это 50+ ссылок. Добавьте поле «Фильтр по разделам» (тот же search.js с другим индексом) или хотя бы якорные ссылки на секции. Сейчас найти «Оферту» можно только скроллом.

3.6. Sitemap::pages() — проверить hidden Средний

Page::listInTheme($theme, true) — второй аргумент $includeHidden = true. Убедитесь, что страницы с hidden: true действительно должны попадать в sitemap. Если это служебные — фильтруйте по $page->hidden.

4Архитектура и тесты

Не срочно, но с текущим размером любая правка Seo требует держать в голове весь файл.

4.1. Разделить крупные классы Средний

  • Seo.php (400+ строк) → Meta, JsonLd, Robots;
  • Chat.php → Intent, Responder, Guard;
  • Search.php → Indexer, Ranker, Snippets.

4.2. tools/chat-check.php — расширить Средний

Добавьте кейсы:

  • пустой ввод: Chat::answer('') → rejected: true, без исключения;
  • очень длинный ввод (10 000 символов) → не падает;
  • Unicode: й vs и + combining, ё vs е;
  • TextFilter::has('shitake') — зафиксировать текущее поведение (true) как известное ограничение, или whitelist + тест false;
  • Chat::answer('абырвалг оплата') и Chat::answer('оплата абырвалг') → проходят;
  • rate limiting: 16 запросов подряд → 16‑й получает 429.

4.3. Golden‑тест для Seo::jsonld() Средний

Зафиксируйте эталонный JSON для /, /pricing/, /blog/tech/some-post в tools/fixtures/. При правке Seo сравнение покажет, что изменилось. Ловит регрессии, которые check-seo не видит (он проверяет наличие, а не форму).

5UX/UI — быстрые победы

Чат

  • автофокус на поле ввода при открытии <dialog>;
  • индикатор «печатает…» перед ответом (пригодится, когда появятся интенты с задержкой);
  • кнопка «Связаться с человеком» в конце ответа.

Поиск

  • сохранение последних 5 запросов в localStorage и показ их при пустом поле;
  • aria-busy="true" на контейнере результатов во время загрузки индекса (aria-live на статусе уже есть — хорошо).

Карта сайта

  • lastmod для статей — показывать «обновлено 12.11.2026» рядом с заголовком.

7Что бы я не делал сейчас

✕

Серверный поиск / Elasticsearch. При 67 статьях клиентский индекс ~20–40 КБ — быстрее и приватнее. Порог для пересмотра — 300+ статей или индекс > 500 КБ.

✕

ML‑модель для интентов. Rule‑based покрывает 90% запросов при 1% сложности.

✕

Модерация форм через TextFilter. Решение «не блокировать» задокументировано и верно: потеря заявки дороже мата в комментарии.

Один вопрос к вам

Есть ли данные о том, какие запросы в чат/поиск сейчас дают rejected или пустой результат? Если да — приоритеты 1 и 3 можно уточнить под реальные формулировки пользователей, а не под гипотезы.
