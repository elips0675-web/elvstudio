2. Комплектация как в библиотечном сайте: FAB → Telegram, WhatsApp, телефон, e-mail,

   Если контактов нет, кнопка открывает чат сразу, а без чата — сразу форму.

3. ИИ-консультант без внешних ключей: `Classes\Chat::answer` (`classes/Chat.php:18`)
   отвечает по каталогу и настройкам — тарифы (`$79,00 / $249,00 / $499,00` из

   что входит, установка (October 4.4+, PHP 8.3+, MySQL 8.0+), оплата, лицензия и

   Ссылки ведут на якоря главной (`#pricing`, `#modules`, `#features`, `#blog`), пока
   страниц нет. Вопрос про конкретный модуль («Сколько стоит Booking?») отвечает ценой
   модуля (`classes/Chat.php:271`), остальное — общими тарифами. `POST /chat` —
   `classes/Http/ChatController.php`, ответ `{ok, answer, chips, link, open}`; лимит
   отдельный — 40/мин (`routes.php:25`), формы остались на 20/мин (`routes.php:18`).
   Ответы рендерятся через `textContent` (без вставки HTML), CSP не менялся.

4. Фильтр грубых слов (`classes/TextFilter.php:36`): основы слов, между буквами
   допускаются пробелы и знаки, повторы букв и латинские похожие буквы. Проверено:
   `хуй`, `х у й`, `х*й`, `х-й`, `пиззда`, `п*зда`, `п.з.д.а`, `xyй`, `блядь`,
   `нахуй это`, `fuck you`, `fuсk` (кириллическая «с»), `f*u*c*k`, `s.h.i.t` — отказ
   («Давайте без грубостей…», само слово не повторяется), следующий нормальный вопрос
   отвечается как обычно. Ложных срабатываний нет на `с указом всё понятно`,
   `потребитель`, `Египет`, `хлеб`, `поэт`, `бал`, `дуб`. Слово с выброшенной буквой
   (`хй`) не ловится — зафиксированное ограничение, а не баг.

5. **Найден и исправлен системный баг инлайна.** `Assets::minifyJs` резал строки
   через `preg_split('~\R~')` без флага `u`: PCRE считает переводом строки байт `0x85`,
   а это второй байт русской «х». Строка `'…подробнее — от двух символов.'` разорвалась
   посередине, браузер падал с `SyntaxError` (HTML-строка 1270), и не запускался весь
   виджет — меню и чат молчали. Заменено на явные `\r\n|\r|\n`
   (`classes/Assets.php:75`), в докблоке зафиксировано, почему `\R` здесь нельзя.

6. Демо-контакты: `Demo::contacts()` (`classes/Demo.php:69`) заполняет `email` и
   `telegram`, только если владелец их ещё не задал; повторный `elv:kit:demo` даёт
   0/0/0 и настройки не перетирает. В `Settings` (`models/settings/fields.yaml`)
   добавлены `whatsapp` и переключатель `chat_enabled` (по умолчанию включён).

здоровается, отвечает на 12 вопросов; отправка формы из виджета → строка в

(Stage 2 — 14.11.2026) — **Админка открывалась без стилей, брендинг был от чужого проекта, Lighthouse 97 → 100.**

1. `php artisan serve` отдавал статику как HTML. `server.php:29` подключает
   `tools/serve-static.php`, а каталога `tools/` в инсталляции не было: `require`
   падал на каждом `/modules/...`, `/themes/...`, поэтому `/admin` приходил с
   `text/html` на CSS/JS — страница входа выглядела как «абы что».
   Скопирован `tools/serve-static.php` (gzip + ETag + правильный `Content-Type`).
   Там же `Cache-Control`: `immutable` только для файлов с `?v=` (ассеты October
   версионирует), остальные — `no-cache, must-revalidate`, иначе браузер держал
   старый логотип и правки не были видны до жёсткой перезагрузки.

2. Брендинг админки был скопирован из библиотечного проекта: `config/backend.php`
   (`app_name` «Библиотека 2026», `tagline` «Панель управления библиотекой»),
   `app/assets/images/{logo,menu-logo,favicon,dashboard-icon}.svg` с надписью
   «Библиотека 2026», `app/assets/css/brand_styles.css` с комментариями `//`
   (невалидный CSS) и ссылками на тему `elv`. Заменено: новые SVG-знаки
   `*-elv.svg` (палитра лендинга `#1c5cf0`/`#6f8bff`), чистый CSS с `/* */`,
   `tagline` → «Панель управления сайтом», часовой пояс `Europe/Minsk`,
   удалены ключи на несуществующие `login_wallpaper.png`/`loginimage.png`.

3. Lighthouse Performance: было 97 (mobile) / 96 (desktop), стало **100 / 100**.
   Причины и правки:
   - HTML отдавался без сжатия — 107 621 байт (`uses-text-compression`: экономия
     86 KiB). Добавлен `Classes\CompressResponse` (gzip ≥ 1 КБ, только фронтенд,
     заголовок `Vary: Accept-Encoding`): 107 621 → 18 586 байт.
   - инлайн CSS/JS вшивались «как есть». `Classes\Assets` теперь сжимает CSS
     (комментарии, пробелы вокруг `{};,`, но **не** вокруг `:` — `a :hover`
     и `a:hover` разные селекторы) и JS (комментарии, отступы, пустые строки,
     переводы строк сохранены — ASI не ломается).
   - `.reveal { opacity: 0 }` держал карточки невидимыми до срабатывания
     IntersectionObserver — задержка отрисовки била по Speed Index. Эффект
     удалён из `styles.css` и `app.js` (визуал не изменился, карточки видны сразу).
   - `themes/elv-studio/assets/img/favicon.svg` не существовал (404 на каждом
     хите) — создан.

Проверено: `/` mobile — Performance **100**, FCP 1.1 s, LCP 1.2 s, TBT 0 ms,
CLS 0, SI 1.6 s; desktop (2 прогона) — **100 / 100**, FCP 0.5/0.4 s, LCP 0.6/0.5 s,
SI 0.8/0.7 s, TTFB 370/300 ms. `curl` с `Accept-Encoding: gzip` → `Content-Encoding: gzip`,
18 586 байт. `/admin` — стили грузятся (`text/css`), вход `admin` / `ElvStudio2026!`
работает (POST → 200, дашборд 143 989 байт, в меню новый `menu-logo-elv.svg`).
Сжатый `app.js` проверен `node --check` (exit 0). AJAX-форма: `POST /subscribe`
с CSRF из мета-тега → 201 `{"ok":true}`. Лендинг отсмотрен скриншотом — вёрстка
цела. Консольные ошибки после правок не перепроверял отдельным прогоном.

Ограничение измерения: локальный `php -S` на Windows тратит ~200 мс на любой
PHP-запрос (статику отдаёт 200 мс, Laravel — ~470 мс), поэтому TTFB здесь
не показатель продакшена; на cPanel/LiteSpeed он будет ниже, а скорость
ограничена уже не сервером, а размером документа.
